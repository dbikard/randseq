core

Finding the DNA motifs a strain restricts, from a table of plasmid counts before and after delivery.

What RandSeq measures

A library of plasmids carrying random inserts is conjugated into a recipient strain. A plasmid whose insert contains a site recognised by an active restriction system is destroyed on entry, so it is depleted relative to the input library. This module works back from each plasmid’s depletion to the motifs responsible.

The method in four sentences

Every plasmid gets a log2FC: how much rarer it became after delivery. Every motif gets the plasmids that contain it, and so a set of log2FC values. A motif’s score is the fraction of those values below a threshold — what fraction of the plasmids carrying this motif were destroyed. Everything after that is deciding which of the many motifs that score well is the actual site.

In steps:

  1. counts → log2FC per plasmid
  2. score every motif of every requested pattern — the scan
  3. keep one description per site, discarding the same site written more or less specifically; set aside a candidate the vector flanks complete unless its sites inside the insert support it
  4. drop a candidate whose score was borrowed from a stronger one
  5. report each motif on its canonical strand, tested against the depletion of plasmids of the same GC content, with a degenerate site written as one IUPAC motif

Steps 3 and 4 are two halves of one problem: one real site makes many motifs score well. Step 3 compares motif strings; step 4 compares the plasmids motifs are found in, which relates descriptions too different for a string rule.

The example data

  • countsTable.csv.gz — 19 recipient strains, with the donor MFDpir as the input library; 11,629 inserts of 20 nt
  • counts_panel.csv.gz — 8 recipient strains and two donor replicates (Control_R1, Control_R2), each strain picked to exercise one behaviour of the pipeline (example_data/counts_panel_key.csv says which); 34,217 inserts, mostly 150 nt

E. coli JJ1886 is in both, so two measurements of one strain must agree on which motifs they call and on which strand they name them.

Step 2: score every motif

Every motif of every pattern is scored over left_flank + insert + right_flank, on both strands. A pattern is the shape of a site, (d1, spacer, d2): defined bases, undefined gap, defined bases. (6, 0, 0) is a contiguous site like GGTCTC; (3, 4, 4) a bipartite site like CACNNNNGTAT. get_patterns() returns the shapes REBASE records for Type I, II and III systems; a site whose shape is not searched cannot be found.

The flanks are scanned because a site can straddle the junction between insert and vector. In the 150 nt panel library the left flank ends in AAAC, so every insert that starts NNNNGTC completes B156’s site AAACNNNNGTC: 382 of the 894 plasmids that carry the site in B156 carry it across the junction.

A motif is counted once per plasmid, however often it occurs there, and a motif and its reverse complement are one motif. Thresholds keep one convention throughout the package: a log2FC threshold is strict (log2FC < thr), a score or support threshold inclusive (>= thr, so min_support=3 means three supporting plasmids, not four).

On the example library

From here on the examples use JJ1886 in the 20 nt library: the inserts with their flanks (get_lib_seq_context), their log2FC, and each plasmid’s background — the depletion rate of plasmids of similar insert GC content, which every test is taken against (plasmid_background in 01_utils explains why). _scan_candidates scans one pattern and keeps the motifs that pass the support and score thresholds. It returns three things: the candidates, with motif, fraction_depleted, num_sequences, avg_log2fc, p_value and pattern (as a string); the p-value of every motif with enough support to be a test, survivor or not; and the pattern’s totals from _scan_pattern, so that later steps look motifs of this pattern up rather than scan it again. The p-values are returned because the Benjamini-Hochberg correction needs the full set of tests, and only this step sees it: a motif that fails the score threshold was still tested.

Step 3: one description per site

The scan returns one site described several ways. In this library the Type I site CACNNNNGTAT also comes back as CACNNNNGTA, one base shorter, and CACNNNNGTAC comes back once for each base pinned at the first position of its spacer (CACANNNGTAC, CACCNNNGTAC, …). Step 3 keeps one description per site, with one tool and three rules applied in this order:

  • the variant profile: pin one position next to a motif to each of A, C, G and T, and score the four motifs
  • rule 1, a mixture is not a site: drop a motif when some position next to it splits its four variants into depleting and not
  • rule 2, a one-base extension of a site is redundant: drop a motif that is a rule-1 survivor plus one defined base
  • rule 3, a motif with an uninformative base is not the site: drop a motif when putting N back at one of its defined bases gives four bases that all behave like the site

The variant profile

_variant_profile scores a set of related motifs — typically the four bases at one position — from the counts step 2 made (_scan_pattern), so a variant is scored exactly as the scan scored it, and a pattern is scanned at most once however many motifs need it. The counts are kept in totals, a dict by canonical pattern that holds for one library, log2FC, background and threshold; the pipeline shares it across calls, so a pattern step 2 scanned is never scanned again. A motif that has no code — an IUPAC letter, or a defined base in the spacer — gets n = 0 and nan for its score and background.

A profile is a mixture when its variants split: some fail the score threshold the candidate had to pass, and the variants spread by at least that threshold. Rule 2: a one-base extension of a site is redundant

A rule-1 survivor has nothing to split at any position next to it, so a candidate that is that motif plus one defined base adds nothing: rule 1 scored all four bases at that position and found no difference. The filter does not compare every pair: _parent_motifs lists the motifs a candidate could extend, and the filter looks them up among the survivors, on either strand (_is_extension is the pairwise definition it is tested against). When the four bases are too thin to judge, rule 1 keeps the shorter motif and rule 2 drops the extension: with no evidence that the extra base matters, the simpler description is kept.

def _is_extension(specific, general):
    """Is `specific` the motif `general` with one more defined base, on either strand?

    The extra base sits one past an end of `general` or at an edge of its spacer -- the
    positions `_undefined_positions` tests. Both strands are checked because every pattern is
    searched in one canonical form, so adding a base to a motif's longer side can turn its shape
    into the mirror form, which the scan writes on the other strand: `TACNNNNGTGA` is
    `CACNNNNGTA` with a base added on the left.
    """
    defined = lambda m: len(m) - m.count("N")
    return defined(specific) == defined(general) + 1 and _find_broad_in_specific(specific, general)

Rule 3: a motif with an uninformative base is not the site

Rule 2 needs the shorter motif to be a candidate. When it fell short of the thresholds, a longer motif can still clear them because its extra base happens to pick out the most depleted of the shorter one’s carriers. Rule 3 asks from the other side: put N back at one of a candidate’s defined bases and classify the other three bases there. If every one behaves like the site, the candidate’s base carries no information.

A base is classified by comparing two models of its carriers — depleted at the site’s rate, or at their own background — by their log-likelihood ratio, which grows with the number of plasmids and so is also the confidence: a base is classified when one model fits ten times better. Simpler criteria fail: a fixed cut-off between the two rates misplaces the boundary, which depends on both, and a test against background calls site-like a base depleted at four times background but a quarter of the site’s rate. The site’s rate is the candidate’s own, re-estimated once from the candidate pooled with the bases first found site-like, because a candidate selected for scoring high overstates it.

Rule 3 drops a motif when, at one position, every other base is site-like. When only some are, the position is degenerate, and reporting writes it as an IUPAC letter (below).

The positions tested (_relax_positions) are those rule 1 tests from the other side: every base of a contiguous motif, an interior one becoming a one-base spacer, and for a gapped motif the outer and the spacer-side base of each half, as long as the half keeps a defined base. _classify_bases classifies the bases at one position; _classify_positions does it at each position asked, profiling a motif of A, C, G and T from the scan’s counts (_variant_profile) and one with an IUPAC letter on the carriers of its instances (_union_profile).

Sites completed by the flank

Reading the flanks with each insert has a cost. The flank is the same in every plasmid, so where a motif uses flank bases it is a shorter motif of the insert at one fixed position, and whatever depletes those inserts scores for the motif too. Without this check, TA249 and ROAR8 in the 20 nt library are called for DCAANNNNNNTAGA, on 159 carriers; 157 of them read its TAGA in the right flank (GTTTTAGAGC…), so on them the motif is DCAA at insert positions 15–18. A real site completed by the flank also restricts where it lies wholly inside the insert: JJ1886’s RTACNNNNGTG needs the flank on 199 of its 212 carriers, and its 13 internal carriers are all depleted.

So a candidate that needs the flank on more than half its carriers (junction_share > 0.5) must stand on its internal carriers, those with a site wholly inside the insert, by the tests a call passes: at least min_support of them, the lower bound on their depleted fraction at score_thr, and their depleted count significant against their background (p < q_threshold). At 0.5 or below the internal carriers are at least half the support and the call already rests on them, so the trigger is fixed. The check runs between steps 3 and 4: step 4 lets a stronger candidate claim a weaker one’s plasmids, and a candidate the flank completes would claim them as readily as a site. _carriers(..., inside=True) reads the internal carriers off the windows that find the carriers: a window is inside the insert when it starts after one flank and ends before the other.

Reporting

A motif and its reverse complement carry identical statistics, so each reported motif is put on its canonical strand (canonical_motif, 01_utils), its pattern mirrored to follow it: a site comes back as GGTCTC, never GAGACC, in every run and every dataset of the same strain.

Is the depletion one population or two?

A real site shifts its carriers as one population. A shadow of another site is a mixture: the carriers that also carry the real site are destroyed, the rest untouched. Sarle’s bimodality coefficient exceeds 5/9, its value for a uniform distribution, when a distribution has two modes — but also when the carriers fall into two depleted groups: CACNNNNGTAC on the 20 nt JJ1886 library has 19 carriers between −6.6 and −4.4 and one at −8.6, a coefficient of 0.654. So bimodal also requires that, split in two where they separate best, the upper group is not depleted (its median at or above log2fc_thr); bimodality keeps the raw coefficient. A shadow is significant and bimodal, a weak real site significant and unimodal, so both are reported; bimodality does not block a call.

_annotate_significance adds these two columns to the result table, with the p- and q-values and the bound on the depleted fraction (Reading the result table, below).

One other base is site-like and two are not, so the position is degenerate and becomes R. _generalise_motif applies this to every defined position of a call, one position at a time — the one whose site-like bases have the most carriers, the first on a tie — and classifies the merged motif again on its own carriers until nothing changes. A merged motif’s carriers are the plasmids carrying any of its instances, counted from the presence matrix, since one plasmid can carry two.

Reading the result table

find_restricted_motifs returns the called motifs in five columns: motif, num_sequences, fraction_depleted, avg_log2fc and q_value. With all_motifs=True it returns every motif that reached scoring, called or not, with all the columns below.

  • How strong is the effect? fraction_depleted is the share of carriers depleted, and avg_log2fc says how far they fall. Compare fraction_depleted with background, the rate at which plasmids like the carriers deplete anyway (plasmid_background): 381A’s CCTNAGG depletes 0.74 of its carriers against a background of 0.30 (The example panel at a glance, below), EDL933’s CACNNNNNNNCTGG 0.91 against 0.09.
  • How sure are we? p_value is the binomial probability of at least this many depleted carriers at their background rate, and q_value adjusts it over every motif the scan tested in the sample (01_utils, Is a motif’s depletion more than the sample’s own noise?). A call needs q < q_threshold.
  • Are most carriers depleted? fraction_depleted_lower is a 95% lower bound on the depleted fraction, and a call needs it at score_thr too. On the 20 nt JJ1886 library CTTNCACA has 10 of 20 carriers depleted (q = 7·10⁻⁵) but bounds the fraction only at 0.30; GGTCTC, 9 of 9, bounds it at 0.72.
  • Does it need the flank? junction_share is the share of carriers with no site wholly inside the insert. Above 0.5 a call also needs its internal_n internal carriers to pass on their own: internal_fraction_lower at score_thr, internal_p_value below q_threshold (Sites completed by the flank). A candidate that fails this is listed only when it would otherwise be called.
  • Is it one population? bimodal marks carriers that mix destroyed and untouched plasmids; bimodality is the raw coefficient.
  • Is it a degenerate site? merged_from lists the variants an IUPAC motif replaced, and is empty for every other row.
  • Why called or not? called is the verdict, and reason (call_reason) says it in words: called, or each test that failed with its numbers. A called row whose carriers are bimodal says so, since that is worth a look before trusting the call.

Running the pipeline

Steps 2 to 4 and reporting, on one sample. Thresholds too loose for a sample can leave step 3 with tens of thousands of candidates, which step 4 would compare for minutes; past max_candidates the pipeline raises TooManyCandidatesError instead of returning a table. A count that large usually means the thresholds are too loose for the sample, not that the strain has thousands of sites.

find_restricted_motifs expects log2FC as calculate_log2fc returns them, median-normalised, and uses them as given: normalise values computed elsewhere the same way. Every test is against the GC-matched background of plasmid_background. On the arguments:

  • log2fc_thr, −0.5 by default, is relative to the sample’s median plasmid: low enough to see weakly restricting systems such as BREX, which −1 misses.
  • min_support: with every carrier depleted, the lower bound on the depleted fraction is 0.22, 0.37, 0.47 and 0.55 for 2 to 5 carriers, so 5 is the smallest support that can be called at score_thr=0.5 (4 at 0.45, 7 at 0.65). Lower only adds candidates and runtime: E1114 on the 20 nt library exceeds max_candidates at 2 to 4.
  • score_thr: a candidate needs this share of its carriers depleted, and a call needs the lower bound fraction_depleted_lower to reach it.
  • q_threshold: the q-value is Benjamini-Hochberg over every motif the scan tested, each against its carriers’ background.
  • max_candidates: step 4’s cost grows faster than the number of candidates. The default, 5000, is above the 3,258 that the busiest strain of the example data (E1114, 20 nt library) brings at the defaults. A caller screening many strains should catch TooManyCandidatesError and record that strain as “no confident call”.
  • patterns: a pattern and its mirror find the same sites, so each is searched once, in one form: (4, 4, 3) is searched as (3, 4, 4).
  • n_jobs: a pattern takes about a second on a 30k-sequence library, so more processes are rarely worth their startup cost.
  • verbose: by default the log counts what each step keeps, and how many of the candidates set aside for the flank would otherwise be called. verbose=True also lists each candidate set aside, marking those, and each candidate step 4 removes, with the stronger motif that explains its plasmids (most of these appear in no table), and each motif scored.
  • encoded_library: encode_library(get_lib_seq_context(log2fc_series.index, left, right)). Strains screened with the same library and flanks share it, so a panel encodes it once; it must describe exactly log2fc_series.index, in order.

The default table holds the called motifs, sorted by q then motif; with all_motifs=True, every scored motif, called rows first (Reading the result table).
